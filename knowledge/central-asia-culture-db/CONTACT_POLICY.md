# 联系前先看当地时间

这是用户明确要求的联系偏好。国家资料、个人作息和默认建议分别保存。

## 每次建议联系时执行

1. 确认客户所在国家或当前所在地，不能只按俄语、号码或国籍判断。
2. 运行 `python contact_planner.py --country KZ --channel email`。默认使用运行当时的UTC时间，再换算客户当地时间。
3. 已知出差时用 `--timezone Asia/Dubai` 等本人确认的时区。已有确认作息时用受控本地 `--profile`。
4. 输出当地日期时间、当前是否合适、下一个候选联系窗口及对应北京时间。
5. 深夜23:00明确提醒：可能正在休息，建议先准备正文，等下个合适工作窗口再联系。不要用北京时间的“明天”代替客户当地日历。
6. 周末、参考节假日、公司休假和本人约定都需要考虑。未知年份、未完整核验的节假日或未确认企业作息应明确说明。

## 示例

```powershell
python contact_planner.py --country KZ --at "2026-10-31T23:00:00+05:00" --channel email
```

会提示：哈萨克斯坦当地10月31日23:00，对应北京时间11月1日02:00；按默认周末避让，下一候选为当地11月2日09:30／北京时间11月2日12:30。资料日历并非完整企业日历，实际发送前仍核对客户安排。

```powershell
python contact_planner.py --country TJ --at "2026-11-05T23:00:00+05:00"
```

参考日历将11月6日列为假日，随后是默认周末，因此候选会顺延到11月9日09:00当地时间，而非直接说次日上午发送。

## 个人作息与兴趣

`customer_schedule.example.json`是空白示意模板。可在受控本地文件中逐步记录本人确认的工作日、联系窗口、免打扰时段、休假日期和愿意分享的饮食音乐偏好。未知睡眠、用餐和爱好保持空白，不根据国家代填；资料应带确认日期。

`confirmed_working_dates`允许明确确认过的特殊工作日；`unavailable_dates`表示本人不方便的日期，并优先于普通工作日。出差时不自动套用原国家假日。真实客户资料不要提交公共仓库。

## 日历与运行范围

`contact_policy.json`内为2026年已查参考快照：哈萨克斯坦有官方来源，其他国家使用标明的二级参考。均未声称完整，宗教日期、补班和企业安排可能变化，2027年等未收录年份会提示重新核验。

此工具只在调用时给建议；没有后台轮询、弹窗、消息队列、自动发送或实际定时任务。准备正文可以继续，已明确约定的联系时间和用户真实选择优先；既有具体授权不需要因默认参数重复询问。
