## 在其他电脑使用

- 这是 Windows 本地工作台源码，不是可直接部署到 GitHub Pages 的静态网站。
- 当前启动脚本、Excel 模板和部分辅助脚本保留了原电脑路径；克隆到其他电脑后需要修改 `start.ps1` 的运行时路径、`app.py` 的 `DEFAULT_BOOK`，并在工作台设置跟进表路径。
- Excel 写入依赖本机 Codex 提供的 `@oai/artifact-tool`，仓库不包含该运行时；可用 `FRIESGO_NODE` 指定 Node 可执行文件。
- 在 `wa-bridge` 内运行 `npm ci --ignore-scripts` 安装锁定版本依赖。首次关联 WhatsApp 需要自行扫码。
- 可选 MCP 安装按 `mcp/README.md` 执行；`mcp/mcp.json` 中的路径需要对应当前安装目录。
- 下载源码不会发送消息；启动后队列默认暂停，实际发送需在工作台明确启动。


邮件发送第一版，运行于Windows本机。Python标准库负责邮件、队列与记录，`@oai/artifact-tool`负责Excel写入。没有云端数据上传，也没有预设邮箱密码。

## 打开

双击 `启动FriesGo.cmd`，浏览器打开 `http://127.0.0.1:8877`。关闭浏览器不代表服务停止；用页面上的“暂停发送”停止后续任务。电脑关机、休眠或服务关闭时不发送。每次重启服务，队列均暂停，需要重新启动。

## 使用

1. 在“邮箱与设置”确认发件邮箱、SMTP及IMAP服务器。Gmail可使用两步验证后的应用专用密码，普通登录密码不适用。也可配置其他支持SSL/STARTTLS的SMTP服务。
2. 默认凭据仅保存在本次运行内存中；可选择使用当前Windows账号的DPAPI加密保存。本工具尚未提供Gmail OAuth登录。
3. 确认跟进表路径。微信原模板为只读，首次启动会在工作区outputs中生成同结构的可写工作表，默认记录到该工作表，原模板保留。保存设置后点击“检查表格结构”。
4. 导入CSV、从跟进表导入客户，或使用“导入已整理的26家公司”。缺邮箱的客户不会生成可发送草稿。重复导入不会自动重置暂停／停止联系状态。
5. 编辑每家公司的英文主题、正文和附件。中文翻译只供查看。预览后逐封加入队列。
6. 点击“启动发送队列”，确认发件邮箱与任务数量。工具按配置的时区、发送日、时间窗口、间隔和每日上限运行。

## 自动跟进与回复

每封首封邮件可附带一封预先编写的自动跟进信，设置0天表示不跟进。启用自动跟进必须启用IMAP；只有最近一次回复检查成功且没有积压时，才会发送到期跟进信。

回复检测读取最近30天的INBOX，通过In-Reply-To／References与本工具发出的Message-ID匹配。匹配人工回复后取消该客户所有待发送任务。自动回复单独记录。独立新邮件、其他收件文件夹、缺失引用头的退信、其他平台回复可能无法自动匹配，需在客户列表手动标记状态。

## Excel记录

- 每次发送尝试持久记录在SQLite中，再写入“跟进记录”；增加“发送状态”“消息编号”两列。
- 同步客户和联系人，保留客户已有的高级业务阶段、暂停和停止联系状态。跟进表日期按北京时间记录。
- “已提交发送服务”只表示SMTP服务接受了邮件，不代表送达或已读。
- 网络中断、程序重启导致无法确认时，标记“结果待确认”，不会自动重发。核查邮箱后可人工确认结果。
- Excel被占用或写入失败时，发送队列暂停；本机记录保留。关闭Excel后点击“补写Excel”。补写不会触发发送。
- 重复补写按消息编号去重；记录达到200行时自动扩容，扩展公式和表格范围。
- 每次替换Excel之前自动备份到 `data/backups/`。写入过程中若原表变化，会放弃替换并保留原表。
- `.friesgo.lock`用于防止并发写入。如果程序恰在写表时异常退出，确认没有其他写入任务后可手动删除该锁文件，再补写。
- 日志保留完整发送正文和回复文本摘要；Excel中写内容摘要及本机详情链接。不要删除 `data` 目录。

## 多联系方式（默认策略：全部分别尝试）

用户长期偏好：同一公司有多个邮箱或WhatsApp候选号码时，逐一检查并分别准备，不能因第一个号码未开通而放弃后面的号码。客户资料新增「全部邮箱」「全部WhatsApp候选号码」，支持每行一个，邮箱也支持逗号／分号分隔。标准化后去重，保存于 customer_contacts；既有资料、历史检查和消息中已知联系方式在首次升级时自动归并，不猜测新号码。

邮件和WhatsApp编辑框默认勾选「本公司全部联系方式」。预览时逐一列出实际收件人及跳过原因，再按明确消息ID加入对应渠道队列。每个邮箱独立一封邮件，不使用群发收件人列表。WhatsApp逐号检查，未开通及查询失败分别记录。已发送、已有待发任务或结果待确认的同一渠道地址跳过；不同渠道分别处理。规划与查号不发送，不自动重发历史邮件；保持原有发送间隔、上限、写表和收到回复停止后续任务的行为。

SMTP明确拒绝某个收件地址时，如果同公司还有其他已排队邮箱，继续尝试其他邮箱；账号／网络／未知结果仍暂停。已有联系和草稿不因升级自动加入发送队列。查询和规划接口为 /api/contacts/check-whatsapp、/api/contacts/prepare；原队列API仍只操作调用者提供的消息ID。

MCP whatsapp_list_customers 返回完整邮箱／号码列表和默认策略；未指定number的whatsapp_check_number会检查同公司全部已保存号码。MCP进程重新连接后加载新实现。

## CSV列名

支持UTF-8 CSV，列名：客户编号、公司名称、国家／地区、邮箱、电话、官网、备注、主题、英文正文、中文翻译。只填写公司名称也可以导入档案，发送前必须补齐邮箱和正文。每封邮件只允许一个收件人。

## WhatsApp（普通账号关联设备）

1. 打开左侧「WhatsApp」，点击「连接 WhatsApp」。专用 Chrome 窗口显示二维码。
2. 在手机当前 WhatsApp 账号中打开「已关联设备」→「关联设备」，扫码。工作台显示发件号码后核对账号。
3. 点击客户行的「WhatsApp」，填写一个完整国际号码（如 +84…）和消息。普通电话不保证开通了WhatsApp。
4. 预览并加入队列，再启动 WhatsApp 队列。连接或保存草稿不会发送。无需先保存手机联系人。
5. 每次尝试先保存本机结果，再写入现有跟进表的WhatsApp渠道；失败、超时、断线或写表失败暂停，结果待确认不自动重发。送达/已读回执更新原记录，不增加发送次数；客户可能关闭已读回执。

首版支持文字、独立队列、每日上限（UTC）、发送间隔、回复后取消待发送任务、人工核对未知结果。邮件与WhatsApp队列互相隔离。每条队列消息绑定关联时的发件号码，换号后无法继续发送旧队列。

采用非官方 whatsapp-web.js 1.34.7，受WhatsApp Web变化影响，也有账号受限风险。不是官方商业接口。关联的浏览器必须保持运行；关闭工作台页面不等于暂停队列，请使用暂停按钮。程序重启后队列暂停，需要重新点击连接，已有有效关联通常无需再次扫码。

关联数据保存在 `data/whatsapp/session`，不要复制或分享。可在手机「已关联设备」取消关联。消息提交去重记录保存在 `data/whatsapp/outbox`，不要删除后重试未知结果。

安装依赖（已有Chrome，无需下载Chromium）：在 `wa-bridge` 目录运行 `npm install --ignore-scripts`。使用仓库中的 package-lock.json 固定依赖版本。连接进程只经标准输入输出与本机服务通信，不新增公开端口。

## 官网留言（ego lite）

左侧「官网留言」与客户列表中的「官网留言」按钮共用客户档案。默认资料为 BaiJiang Lin / FriesGO Global / friesgoindustrial@gmail.com / +86 17731796591，可在本页面编辑；不会覆盖邮件发件账号。提供两种明确模式：

- 自动填写和预览：查找 Contact 入口、识别常见联系表单、按字段填写并回读核对，保留 ego lite 页面和本机字段记录。不会点击 SEND、Submit 或 PREVIEW。
- 自动填写并提交：用户选择该模式并启动官网队列后，无逐条确认弹窗。只有必填项齐全、正文回读一致、无交互验证码且提交按钮唯一时才提交。PREVIEW 等多步骤表单转为「需要处理」。

启动队列只执行已加入的任务。默认模式始终是预览；重启服务后暂停。官网任务、正文、执行身份快照和结果存于现有 SQLite 的 website_tasks 表，执行文件保存在 data/website/。预览不会记作邮件发送，也不会增加邮件发送次数；首版官网记录在独立页面查看，暂不写入Excel发送日志。

后台调用 ego-browser CLI，仅使用网页 DOM、fill、selectOption 与网页内点击，不使用系统键盘、剪贴板、Computer Use、窗口恢复或截图。浏览器可在后台；ego lite 自身创建任务空间时仍可能显示界面。验证码、嵌入表单、自定义选择器和未识别必填项会保留已填内容并记录原因，不承诺覆盖所有网站。首版采用确定性字段规则与少量站点适配，基础文案可按产品选择重新生成和编辑，未接入通用AI网站分析服务。

实际提交前会写入 submit-attempted 检查点。网络中断、超时或没有新出现的明确成功提示，标记「提交结果待核实」，不自动重发。暂停和客户停止联系会写入取消标记；已经点击提交的一条可能仍会完成。任务中的对外资料在加入队列时固定，不受后续资料编辑影响。

电话字段填入前去掉空格、括号、点和短横线，保留国际区号与前导加号；原始联系资料和正文不改。填写完成后至少等待4秒，再做提交检查。AL ADRAN 还需等待官方 reCAPTCHA 配置和脚本就绪，未就绪则不点击提交。

回执检测现保存点击回执、JavaScript提示框、留言POST及HTTP响应，最长观察45秒。校验错误弹窗会记录为需要处理，并关闭提示以恢复读取；不会自动同意确认框。HTTP错误不视为成功，也不会自动重发；网站防护拒绝或接口不可达需要单独处理，不绕过验证码或防护。

测试：`python -m unittest discover -s tests -p test_website.py -v`、`node tests/website-rules.test.mjs`。本机表单的 ego lite 实测已验证填写与重复邮箱核对，提交次数为0；不代表所有第三方网站均已适配。

## 号码预检与消息编号兼容

WhatsApp现支持独立号码预检，发送前必须具备同账号下24小时内的已开通检查结果。检查失败与未开通分别记录；查号本身不计为已联系。网页已登录但发送初始化异常时，仅在查询连接独立通过检查后允许查号，仍不允许发送。

wa-bridge/compat.cjs 对固定的 whatsapp-web.js 1.34.7 增加消息键 `_serialized` / `$1` 兼容，参考上游 PR https://github.com/wwebjs/whatsapp-web.js/pull/201850/files 。启动时幂等应用；依赖代码改变会停止并要求复核，不静默修改未知版本。
